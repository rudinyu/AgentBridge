# AgentBridge Feature Plan

[繁體中文](FEATURE_PLAN.zh-TW.md)

- **Status:** Proposed
- **Basis:** AgentBridge 0.8.0 working tree, the 0.6.0 competitive-scan baseline, [Product Gap Study](PRODUCT_GAP_STUDY.md), and first-party CLI documentation
- **Last reviewed:** 2026-11-01

### Product goal

Make AgentBridge the local-first workspace shared by Codex and Claude Code. Users should be able to choose a real signed-in account and plan, work in an isolated workspace, understand the agent's actions, review each change, and explicitly accept the result. Keep using the providers' official CLIs and sign-in flows; do not copy provider credentials or rebuild their native interactive TUIs.

### Current additions — AgentBridge 0.8.0

AgentBridge 0.8.0 adds a subscription-only autonomous workflow with a generated and reviewed dependency graph, selected role accounts, bounded concurrency and repair, exact-diff review, approved verification, persistent status and cancellation. It does not automatically accept, commit, push or merge results. Each provider start continues to use the account's local usage controls. Sharing between roles respects profile consent.

Active Skills/MCP are separate from the legacy metadata registry: reviewed Skill instruction snapshots enter managed prompts, while approved installed local stdio MCP servers run through a per-invocation tool-filtering proxy. Import does not execute anything. Configuration changes and revocation invalidate authorization. Script-backed Skills, automatic installation and remote HTTP/OAuth MCP are outside this initial runtime.

Mac Control is included as a typed preset with target-App enforcement, default Observe mode, additional Control consent, permission-readiness checks and Stop Control. Screen capture includes the entire main display and may reach the selected provider; it is not a target-window crop. macOS permission grants remain manual. See [Autonomous Workflows and Active Extensions](AUTONOMY_AND_EXTENSIONS.md) for architecture, scope and validation boundaries.

These additions require their own build/test and release verification. Acceptance of the 0.7.0 notarized artifact does not establish acceptance of 0.8.0.

### Historical baseline — AgentBridge 0.6.0 (2026-10-27)

AgentBridge 0.6.0 uses English by default and supports English and Traditional Chinese throughout the app UI. Users can change and save the language in the app header; both localization resources are bundled with the app.

The user-selected workspace data root is implemented. On first use, the app asks the user to choose or create a folder; the CLI shares the saved location. Isolated session workspaces and shared memory live there, while private settings, account profiles, session/audit metadata, usage controls, and budget ledgers remain in Application Support. Changing the root copies existing workspaces and memory without deleting the old copies or overwriting conflicting destination data. The app rejects a root inside a Git repository, including a linked worktree.

Cross-provider App/CLI memory is implemented for the same canonical source repository and pinned commit, subject to each account profile's sharing setting. Native provider TUI transcripts are not imported. Users can explicitly carry selected App-owned turns and/or notes to a different commit in the same canonical repository; matching handoffs enter the next allowed target-session prompt as bounded, untrusted JSON with source/target provenance.

All four competitive-scan priorities below are implemented in 0.6.0: isolated reviewed changes, user-started verification and activity reporting, explicit memory handoff, and a task board with metadata-only extension policy. The task board records launched operations only. The App limits its own concurrent work to three different sessions; task records from CLI runs share per-session run locks but not this App concurrency ceiling. Descriptor import and grants never activate provider extensions or execute scripts. The release remains **Proposed** until the signing, notarization, Gatekeeper, and other acceptance gates are verified.

MUST-10 is partially implemented in the current checkout:

- The app shows account-scoped AgentBridge run activity for rolling 5-hour, 24-hour, 7-day, and selected-session windows, with a seven-day chart. Subscription run-count caps can be configured and are checked before managed launches.
- Claude API activity is kept separate from subscription activity. The app and CLI share account-scoped monthly, daily, session, and per-run controls, including a US$140 monthly cap for the built-in Claude profile, a separate required cap for each new Claude profile, conservative reservations, a one-unresolved-call limit, and preflight blocks.
- One-time 50%, 75%, 90%, and 100% alerts are shown in the app and can optionally use macOS notifications. Limit changes and threshold events are stored in a bounded local audit history. Unknown costs remain reserved until manually reconciled against the provider bill in the app or CLI.
- The provider's numeric subscription quota and reset data are not available through a supported machine-readable interface used by this app. After a user explicitly starts `/usage` in the official CLI, the dashboard best-effort parses recognized fields from bounded visible screen text into its unified card; unknown values remain unavailable. This is not a structured quota API, and the official TUI remains the source of truth. Native TUI turns are not recorded or capped.

MUST-10 remains open for user-adjustable alert thresholds and optional confirmation before a managed run at a chosen high-usage threshold. MUST-11 localization is implemented; Developer ID signing, notarization, stapling, and Gatekeeper verification remain release gates. The plan remains **Proposed** until these and the other first-release acceptance gates are met.

### Four priorities from the competitive scan — implemented in 0.6.0

These priorities incorporate capabilities documented by Codex, Claude Code, Cursor, and Google Antigravity. Their local-first implementation status is summarized here; cloud execution and provider extension activation are outside this release.

1. **P0 — Safe change and delivery loop (MUST-03–05, MUST-07). Implemented.** Read-only is the default. An isolated-change session requires subscription mode and an explicitly approved reviewable plan before edits; review full file diffs, restore a file, export a patch, or accept/apply only after the current diff passes verification. Apply checks the source base commit and creates an uncommitted worktree on a named local branch. No automatic commit, push, or merge.
2. **P0 — Activity and verification (MUST-01, MUST-06–07). Implemented.** The App shows ordered redacted audit events and launched task records. Verification starts only on user action, runs `.codex/ci.sh` by default, and supports a custom executable plus separate argv after explicit approval. It reports the provider's actual CLI events and verifier executable, argv, working directory, exit status, duration, and redacted output where available; AgentBridge does not claim telemetry the CLI did not provide.
3. **P1 — Project memory and explicit handoff (MUST-08). Implemented.** Same-repository cross-commit carry-forward requires explicit turn/notes selection and a target bound account that allows shared memory. Only matching handoffs are supplied to the target session's next provider prompt, as bounded JSON-marked untrusted historical context with source/target provenance. Native TUI transcripts are excluded.
4. **P1 — Parallel work and governed extensions. Implemented as local task tracking and inert policy metadata.** The task board records actual launched operations, per-session progress, approval state, cancellation, and diff/verification references. The App limits its own work to three different concurrent sessions; the CLI also uses process-level locks to prevent overlapping managed runs in the same session. Skills/MCP descriptors are inert imports; explicit per-project grants store narrow permission metadata only. They do not activate extensions, connect MCP servers, or execute setup scripts. ### Must ship before the first distributable release

Every item below is a release requirement. Do not claim safe code modification is complete until every item passes acceptance.

| ID | Required feature | Required behavior and acceptance |
| --- | --- | --- |
| **MUST-01** | **Project and session workbench** | Organize work as Project → Sessions/Tasks, with Chat, Changes, Terminal, and Activity in the workspace. Each session has an identifiable title, status, and project. Users can find current and recent work; search, archive, and advanced filters may follow after the first release. |
| **MUST-02** | **Real account and plan switching** | Show the actual Codex/Claude profile, CLI-verified sign-in state, and plan fields reported by the CLI. Bind every session to the account selected at creation. Switching accounts must switch the actual CLI profile, not just a UI label. Before a new session starts, show provider, account, reported plan, repository, and base commit. |
| **MUST-03** | **Clear execution modes and permissions** | Offer Read-only analysis, Isolated changes, and Native interactive CLI modes; default to read-only. Keep provider, account, workspace, base commit, writable scope, network/tool permissions, memory state, and cancellation visible while a run is active. Preserve the official Codex/Claude TUI in native interactive mode; do not imply its transcript is audited by AgentBridge. |
| **MUST-04** | **Isolated changes and reviewable plans** | Make code changes only in an AgentBridge-managed isolated clone/worktree and separate branch, pinned to a recorded base commit. Never edit the user's source worktree first. For non-trivial work, present a reviewable plan that users can adjust, comment on, approve, or cancel before file writes begin. Cancellation/failure must clean up child processes and leave the workspace state clear. |
| **MUST-05** | **Changes diff, acceptance, and recovery** | Show changed files and file-by-file diffs. Users can reject one file or the whole result, restore the isolated workspace, or explicitly export a patch/apply to a named local branch. Before applying, compare the source repository/base commit; stop for review if it changed. Never commit, push, or merge automatically. |
| **MUST-06** | **Activity and approval timeline** | Present plans, tools/commands, approval requests, file changes, verification, retries, errors, waiting, and cancellation as readable steps. Allow safe, redacted command output to expand. The UI must answer what is happening, which files changed, whether approval is needed, and whether the run is complete. Cancellation must terminate AgentBridge-launched process groups; never mark a live process as stopped. |
| **MUST-07** | **Verifiable results** | Before accepting code changes, allow the project's existing `.codex/ci.sh` or a user-selected test command to run in the isolated workspace. Show the command and working directory first; require approval for custom commands and launch them as an executable plus argv, never by interpolating shell text. Require separate approval for network or elevated operations and redact sensitive output. Show each result, exit code, duration, and reason for skipped checks. Never present failure as success. |
| **MUST-08** | **Cross-provider shared memory and handoff** | Share memory across App/CLI and Codex/Claude using the same canonical repository path and pinned commit. New accounts share by default and can explicitly opt out. Before each run, show which memory will go to which provider; identify memory provenance and account scope. Do not scrape native TUI transcripts. Let users save a handoff summary with goal, decisions, completed/remaining work, files, commit, and verification results. Carrying selected memory to a later commit must be an explicit, reviewable user action; never silently mix branches or projects. |
| **MUST-09** | **Claude API authorization and spend ledger** | Subscription login is the default; subscription quota exhaustion must never trigger paid API use. Show API controls only when Claude API is explicitly selected; Codex must never show them. Require a per-call key, spend confirmation, and run cap; keep the key process-scoped. Share the ledger between App and CLI, scoped to the selected Claude account profile; never merge accounts by display name. The user's current Team account has a stated US$140 monthly allowance and uses that as its default local cap. A new Claude account must have its own cap explicitly configured and cannot inherit the other account's allowance. Reserve concurrent spend before launch, block a run that exceeds the remaining cap, and never treat unknown cost as zero. Explain that this local ledger cannot see use outside AgentBridge and is not an Anthropic hard cap. |
| **MUST-10** | **Quota visibility, alerts, and usage controls** | Keep provider-reported subscription quotas separate from AgentBridge-tracked API spend. For the selected account and plan, show every provider-reported usage window separately—such as a 5-hour/session window and a weekly window—with usage/remaining amount, reset time, source, and last refresh. Plan windows vary by provider and plan; show only windows the provider confirms, and do not assume every plan has both. Use a documented, supported CLI status/usage interface; do not scrape private account endpoints or native TUI transcripts. If there is no supported numeric data, say “Unavailable” and offer the official status/usage command as a manual check. Keep AgentBridge-tracked runs/turns in a separately labeled local meter; never present them as account-wide usage because provider allowances may be shared with other provider apps. Send configurable in-app and macOS alerts at 50%, 75%, and 90% for each measurable window, once per window period; if only exhaustion/reset is reported, alert on that signal. Show each window's independent reset time where available. At 90%, allow the user to require confirmation before the next AgentBridge-managed run; at confirmed exhaustion, pause/block new AgentBridge-managed runs until reset or an explicit user choice. Never switch to paid API or another account automatically. For each Claude API billing account/budget pool, show the local monthly cap, spent, reserved, remaining AgentBridge budget, and reset date/time; do not label local remaining budget as provider credit balance. Default one-time API budget alerts at 50%, 75%, and 90%, plus an alert and hard block at the cap. Allow per-account monthly, daily, per-session, and per-run caps; require explicit configuration for additional billing accounts. Limit concurrent paid calls to one by default and reserve across App and CLI before launch. For subscription runs, allow account-level daily/session run or turn limits for AgentBridge-managed chat. Native interactive TUI usage cannot be fully metered or capped by AgentBridge; disclose this before launch. Let users adjust warning thresholds and disable future Claude API calls. Muting notifications must not disable limits or hard blocks. Reject an over-limit run before launch. Audit cap changes, reservations, settlements, alerts, and blocked runs without recording secrets. Warn that canceling an active call cannot reverse charges already incurred. |
| **MUST-11** | **Localized UI, separate language files, and a distributable app** | Default the app UI to English and include English and Traditional Chinese localizations with a saved in-app language picker. Keep English in the canonical README.md, ARCHITECTURE.md, FEATURE_PLAN.md, and HOW_TO_USE.md files, with separate `.zh-TW.md` counterparts; update user flows and safety limits with each relevant feature. Before public distribution, sign with Developer ID, notarize/staple, and verify Gatekeeper installation. Do not describe an unsigned development build as a ready-to-install release. |

### Required end-to-end workflow

1. **Start:** Choose Project/repository → provider → real account/plan → Read-only, Isolated changes, or Native interactive → review permissions, base commit, memory, and any Claude API budget.
2. **Run:** For changes, review and approve the plan first. Work in isolation. Activity shows progress, tools, approvals, files, and verification; the user can cancel.
3. **Review:** Inspect the full diff and checks in Changes; reject or accept file by file. Check for source-version conflicts before exporting a patch or applying to a named branch.
4. **Handoff:** Switch Codex/Claude on the same repository/commit, inspect memory provenance, and pass an explicit handoff summary. Never read or import provider-private transcripts.

### First-release acceptance gates

- The source repository remains unchanged until the user accepts the result. Cancellation, failure, and diff rejection leave no source edits or orphan processes.
- Every change session exposes provider/account, base commit, permissions, plan, complete diff, verification results, and final status.
- Switching Codex/Claude profiles makes the CLI use the selected account; changing the global selection never silently changes an existing session's account.
- Codex UI never shows Claude API. Subscription and API modes never fall back into one another. Every Claude API call is explicitly authorized and charged to the selected account's own local ledger; the current Team account starts with the stated US$140 monthly cap, while additional accounts require their own configured cap.
- The usage panel separates provider-reported subscription quotas from API spend. For each reported plan window (including 5-hour/session and weekly windows when applicable), it shows usage, remaining amount, reset time, data source, and last refresh; it never assumes every plan has the same windows.
- Provider quota alerts use only documented, supported machine-readable status/usage data. When no such numeric source exists, the UI says “Unavailable” and offers an explicit user-triggered official CLI `/usage` view; it may best-effort parse only bounded visible screen text after that action, with unknown fields marked “Not provided.” It does not read arbitrary terminal transcripts or private endpoints. Local AgentBridge run/turn counts remain a separate estimate and are never labeled account-wide.
- Default 50%, 75%, and 90% notifications fire once in each measurable window period. Reaching confirmed exhaustion alerts and blocks new AgentBridge-managed runs, while each window's reset is shown independently where available. No API or account fallback is automatic.
- A user can require confirmation before the next AgentBridge-managed run at a configured threshold such as 90%. Muting macOS notifications never removes in-app quota state or disables limits.
- API monthly spend and caps remain a separate meter; reaching the API cap alerts and hard-blocks new paid calls. A preflight over-budget request is rejected before launch.
- Per-account daily, monthly, per-session, and per-run limits are enforced across App and CLI; concurrent paid calls default to one and cannot race past the reserved balance. Users can lower limits, configure warning thresholds, and disable future Claude API calls.
- AgentBridge-managed subscription sessions stop before exceeding configured daily/session run or turn limits. Native interactive TUI sessions clearly disclose that AgentBridge cannot fully meter or cap provider usage.
- Cap changes, reservations, settlements, alerts, and blocked runs are auditable without secrets. Canceling an in-flight call stops work where possible and records that provider charges may already have accrued.
- Codex and Claude can use allowed memory for the same repository/commit. New accounts share by default; opting out stops automatic reads/writes; included items and provenance are inspectable. Carrying selected context to a different commit is explicit, reviewable, and shows both commits; it never merges branches or projects automatically.
- Failures, cancellation, and CLI format changes show a real error; they are never presented as success, and unknown cost is never recorded as zero.
- A release candidate passes Developer ID signing, notarization, stapling, and Gatekeeper installation checks; the separate English and Traditional Chinese guides match their corresponding UI labels.

### Later work that does not block the first release

- Calendar/background scheduling and mobile/remote monitoring beyond the new bounded local autonomous workflow.
- Browser-specific automation, web previews and recording artifacts beyond the scoped Mac Control preset. Plans, diffs, command output and test reports remain the primary persistent artifacts.
- Remote HTTP/OAuth MCP, Skill scripts, hooks, automatic installation, GitHub issues/PRs and Linear/Slack integrations. Local stdio MCP and Skill instruction activation are covered by the current additions above; old metadata grants remain inert.
- Attachments, images, drag-and-drop, advanced search, bulk rename/archive, historical usage analytics/export, collapsible panels, and localizations beyond English and Traditional Chinese.
- A third model provider. First complete safe changes, review, handoff, and spend control for Codex and Claude.

### Explicit non-goals

- Do not clone the full Antigravity, Codex, or Claude IDE/TUI. AgentBridge owns the cross-provider project, permission, memory, review, and budget workflow.
- Never auto-commit, push, merge, elevate permissions, switch to paid API mode, or widen memory sharing without explicit user consent.
- Do not copy OAuth tokens from official CLIs, parse provider-private transcripts, or describe a local Git clone/worktree as a macOS OS sandbox.
- Do not describe AgentBridge's US$140 local ledger as an account-wide Anthropic hard cap.
